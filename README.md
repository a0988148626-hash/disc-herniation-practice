# Disc_Herniation_Practice — 椎間盤突出 MRI 判讀練習

GitHub（private）：<https://github.com/a0988148626-hash/disc-herniation-practice>

## 專案定位

這是一個練習專案，目的是為達文西機器人脊椎手術影像演算法工作做準備。跟同作者既有的
`Spine_Screw_Practice`（VerSe CT 椎體分割＋螺釘規劃）是同一系列的延伸練習，但目標組織
與影像模態都不同：

| | Spine_Screw_Practice | Disc_Herniation_Practice（本專案） |
|---|---|---|
| 影像模態 | CT | MRI（T1/T2 矢狀面） |
| 目標組織 | 椎體（骨骼） | 椎間盤（軟組織） |
| 核心演算法 | HU 閾值骨骼分割 | 分割遮罩幾何特徵＋輕量分類 |
| 判讀目標 | 螺釘路徑規劃 | 椎間盤突出（disc herniation）二元判讀 |

CT 的 HU 閾值分割邏輯完全不適用於 MRI 軟組織，因此方法從頭設計。

## 資料結構（以實際下載到的檔案為準，非憑空假設）

### `masks/*.mha`（447 個檔案，SimpleITK 可讀取，int16，標籤編碼如下）

直接讀取檔案內容確認的標籤規則（與 Hugging Face 上 `cdoswald/SPIDER` README 的官方說明一致）：

```
0         = 背景
1-25      = 椎體，由下往上編號（L5=1, L4=2, L3=3, L2=4, L1=5, T12=6, T11=7, ...）
100       = 脊椎管（spinal canal）
101-125   = 部分可見的椎體
201-225   = 椎間盤，由下往上編號（L5/S1=201, L4/L5=202, ...）
```

座標軸方向（ITK/DICOM LPS 慣例，所有檔案的 direction matrix 皆為單位矩陣，已用其中一個檔案的
metadata 核對）：

```
array[z, y, x]
  z: 上(+) <-> 下(-)   （頭尾軸）
  y: 後(+) <-> 前(-)   （前後軸）
  x: 左(+) <-> 右(-)   （左右／矢狀面切片序號）
```

### `overview.csv`（每個影像序列一列，39 個欄位）

欄位包含 `new_file_name`（對應 mask 檔名）、`num_vertebrae`、`num_discs`、`sex`、`subset`
（**training 360 筆／validation 87 筆**，合計 447，隱藏測試集未釋出）、以及一系列 DICOM
掃描參數（`PixelSpacing`、`SliceThickness`、`Manufacturer` 等）。

序列組成：t1 共 196 筆、t2 共 210 筆、t2_SPACE 共 41 筆（218 位病人中，有些缺 t1 或缺 t2）。

**重要發現（並非憑空假設，是實際載入檔案後才發現）：不是每個 `.mha` 檔案都是真正的矢狀面
多切片堆疊。** 用 SimpleITK 讀取全部 447 個檔案的 `GetSize()` 後發現，ITK 第 0 軸（本專案
程式假設是「左右切片數」的那一軸）的大小呈現清楚的雙峰分布：373 個檔案落在 8~144（典型矢狀面
堆疊，切片數少、切片間距粗），另外 74 個檔案剛好等於 512（例如病人 161 的 `161_t2.mha` 其實
是 `(512, 512, 19)`——512×512 的方形同平面視野＋只有 19 張粗切片，這其實是**軸切面
（axial）重組影像**，而不是矢狀面；所有 `_t2_SPACE`/`_t1_SPACE` 檔案也都是 512 起頭，因為
它們是近似等向性的 3D 重建，同樣不符合本專案演算法假設的矢狀面幾何）。這個發現解釋了為什麼
最初版本的 `disc_height_mm` 會出現嚴重離群值（見下方「驗證結果」與 `extract_features.py`
裡的 `is_sagittal_multislice()`）——不是單純的雜訊，而是整個影像的幾何假設不成立。

### `radiological_gradings.csv`（1520 列，每個椎間盤層級一列）

欄位：`Patient`、`IVD label`（1~9，由下往上）、`Modic`、`UP endplate`、`LOW endplate`、
`Spondylolisthesis`、**`Disc herniation`（本次判讀目標，二元標籤）**、`Disc narrowing`、
`Disc bulging`、`Pfirrman grade`。

資料品質筆記：有 2 列 `IVD label = 0`（病人 107、152），其餘欄位全為 0 且 Pfirrman grade
欄位為奇怪的佔位值，判斷為資料中的異常／佔位列，已在特徵提取時排除。

218 位病人全部都有分級資料（含 training 與 validation 兩個 subset，隱藏測試集的分級未釋出）。
`Disc herniation = 1` 共 72 列／1520 列（**約 4.7%**），65/218 位病人（約 30%）至少有一個
突出的椎間盤層級——陽性比例偏低，是真實下背痛篩檢族群的合理分布，但也意味著分類任務天生
類別極度不平衡。

## 方法設計：幾何特徵 + 輕量分類（不訓練深度學習模型）

本機沒有 GPU 訓練資源，因此刻意選擇一個「站得住腳但不碰深度學習」的路線：直接利用 SPIDER
官方提供的分割遮罩算幾何特徵，而不是從零訓練分割或分類網路。

### 椎體前緣／後緣的判定（v2：連通元件分析，取代 v1 的逐欄位門檻）

分割遮罩沒有把「椎體（body）」跟「後方結構（椎板、椎弓根、棘突）」分開標註，只有單一的
椎體整體標籤。若直接拿椎體遮罩的最後緣（最大 y）當作「後緣」，會被棘突等後方結構嚴重誤導
（後方結構遠比椎體後緣更靠後）。

**v1（最早版本，已取代）**：以脊椎管（label 100）在同一個 z 切片的 y 方向中心為界，逐個
x,z 位置把椎體體素切成前／後兩群，取前群最大 y 值。缺點：這是逐「欄位」（固定 z,x 的一條
y 方向線）硬切，沒有用到影像本身的形狀資訊，在脊椎管消失或變形的切片容易被騙。

**v2（目前版本，`compute_vertebral_body_border_maps` in `scripts/extract_features.py`）**：
改用**連通元件分析（connected-component analysis）**。矢狀面序列的每一個 x 切片本身就是
一張真實的 2D 影像（z,y 平面）；在大部分切片裡，椎體 body 跟椎板/棘突複合體中間隔著脊椎管，
在影像上是**兩個互不相連的區塊**，只有切到椎弓根（pedicle）的切片兩者才會黏在一起。做法：

1. 對每個 x 切片的椎體遮罩跑 `scipy.ndimage.label`（8-connectivity）得到連通元件。
2. 每個元件逐像素比對同一 z 列的脊椎管 y 中心，用「多數票」判斷這個元件整體算 body（前側）
   還是後方結構（後側）；元件所在 z 列若找不到脊椎管參考，退回用整張切片的脊椎管平均 y。
3. 取被判為 body 的元件們的最大 y（後緣）與最小 y（前緣）。
4. 退化情況（整個切片完全沒有脊椎管遮罩可用）：退回取最靠前的單一元件。

已知限制（誠實記錄，不是隱藏）：切到椎弓根的切片會讓 body 跟後方結構黏成一個元件，多數票
判斷會把整個黏連的元件歸成一類，可能讓該切片的 body 後緣估計偏得比真實皮質邊界更靠後——
這是連通元件法在這個簡化版本下仍然存在的誤差來源，沒有另外做椎弓根偵測去排除。

**v1 → v2 實際影響**：重跑全部 1511 個椎間盤層級，`max_bulge_mm` 平均絕對差異約 0.86mm，
45 列（約 3%）差異超過 5mm；下游分類結果幾乎沒變（AUC 0.675 → 0.674，細節見下）。也就是說
v2 在方法學上更站得住腳（真的用了影像形狀資訊，不是硬切），但對這批資料的最終判讀準確度
沒有帶來實質改善——`disc_height_mm` 的離群值問題（見下方侷限）也完全沒受影響，因為那個
問題跟椎體分離法無關，是椎間盤遮罩本身 bounding box 的問題。

### 每個椎間盤層級抓取的特徵（`scripts/extract_features.py`）

逐一走過椎間盤遮罩（label = 200 + IVD label）所覆蓋的每個 z（頭尾）切片、每個 x（左右）
切片，計算：

- `disc_height_mm`：椎間盤高度估計（v3：每個矢狀切片局部高度的中位數，取代 v1/v2 的全域
  bounding box，見下方「v2 → v3 實際影響」）
- `max_bulge_mm` / `mean_bulge_mm`：椎間盤後緣超出「椎體後緣估計線」的最大／平均距離
- `bulge_normalized`：`max_bulge_mm` 除以相鄰椎體前後徑（AP depth），做尺度正規化
- `asymmetry_mm`：左半邊切片 vs. 右半邊切片的最大突出量差異，粗略偵測是否偏側突出
- `canal_encroach_frac`：有多少比例的切片中，椎間盤後緣已經達到或超過脊椎管前緣
  （代表對脊椎管造成壓迫的比例）
- `mean_disc_ap_extent_mm`：椎間盤在每個切片上的前後徑平均值
- `n_xz_slices_with_disc`：有效切片數量（資料品質參考，不作為分類特徵）

序列選擇：每位病人優先用 `t2`，沒有 t2 才退回 `t1`，兩者都沒有才用 `t2_SPACE`
（T2 對椎間盤軟組織對比度較好，是臨床慣用的判讀序列；這個選擇未逐一比較 t1/t2 兩者的
特徵差異，是方法侷限之一）。**v3 新增**：候選序列若不是標準矢狀面多切片堆疊幾何（見上方
「資料結構」小節的發現），直接跳過改選下一個偏好的序列（見 `is_sagittal_multislice()`）；
218 位病人中有 **20 位**（約 9.2%：病人 18, 22, 35, 45, 57, 69, 78, 107, 110, 127, 129,
136, 152, 162, 166, 177, 185, 220, 234, 239）所有候選序列都不符合，整個病人被排除在特徵表
之外，而不是硬用不符合的幾何算出看似正常但其實無意義的數字。

### 椎間盤高度計算的修正（v2 → v3）

**問題發現過程**：v1/v2 版本的 `disc_height_mm` 直接取椎間盤遮罩在整個體積中的 z 方向
bounding box（最高 z 減最低 z），病人 161 層級 1 出現 **62.7mm** 的離群值（正常腰椎椎間盤
約 8-12mm）。一開始懷疑是零星雜訊體素把 bounding box 拉爆，改成「逐矢狀切片取最長連續
z 區段，再取中位數」之後，這個特定案例只降到 59.4mm——**幾乎沒變**，代表問題不是雜訊，
而是更根本的東西。追查後發現：病人 161 的 `161_t2.mha` 其實是 `(512, 512, 19)` 的**軸切面
重組影像**，不是矢狀面！在這種幾何下，只有 19 張粗切片（3.3mm 間距）覆蓋頭尾方向，椎間盤
在大部分切片都有訊號是正常現象（因為切片本身就很厚、方向也不對），跟椎間盤真正的高度毫無
關係——這是演算法幾何假設整個不成立的問題，不是統計離群值能修的。

**實際修正**：加入 `is_sagittal_multislice()` 幾何檢查（見上方），排除 20 位病人的無效
序列；同時仍保留「逐矢狀切片中位數」計算（對剩下真正矢狀面的資料仍是比單純 bounding box
更穩健的做法）。

### 驗證方式（`scripts/classify.py`）

1. **規則式門檻（baseline）**：`canal_encroach_frac > 0` 或 `bulge_normalized > 1.0` 即判為
   突出。門檻是憑經驗直接設定的「第一次猜測」，沒有另外調參，刻意保留原始的粗糙結果。
2. **Logistic Regression**：標準化後的 8 個幾何特徵，`class_weight="balanced"` 處理類別不
   平衡，用 **GroupKFold（5 折，依病人分組）** 交叉驗證——同一位病人的所有椎間盤層級永遠
   被分在同一折，避免同一人的資料同時出現在訓練與測試集造成的資訊洩漏。

## 驗證結果（誠實記錄，含失敗與侷限）

資料：排除 20 位幾何不符的病人後，**1362** 個椎間盤層級抓到特徵；因 `canal_encroach_frac`
偶發缺值再剔除 1 列，最終進入分類評估的是 **1361 列**（66 陽性／1295 陰性，陽性率 4.85%）。

以下是 **v3**（連通元件分析＋矢狀面幾何過濾＋中位數椎間盤高度）重跑的結果。v1/v2 的詳細
數字已不再列出（歷史比較見上方「v1 → v2 實際影響」「椎間盤高度計算的修正」）；跟 v2 比，
這次（排除 20 位幾何不符病人）**AUC 有實質提升**，見下方數字與解讀。

### 規則式門檻結果（很差，且已誠實保留）

| 指標 | 數值 |
|---|---|
| Accuracy | 0.260 |
| Sensitivity（敏感度） | 0.712 |
| Specificity（特異度） | 0.237 |
| PPV（陽性預測值） | 0.045 |
| 混淆矩陣 (tn, fp, fn, tp) | (307, 988, 19, 47) |

門檻條件把超過七成的椎間盤都判成「突出」，特異度極低（0.237），代表這個規則對大多數
正常椎間盤也會誤判——**這個簡單門檻法本身幾乎沒有臨床篩檢價值**，只是作為「不做任何學習、
純靠解剖學直覺設門檻」的對照組，用來凸顯接下來 logistic regression 有沒有學到東西。

### Logistic Regression 結果（排除幾何不符病人後，AUC 有實質提升）

| 指標 | 數值 |
|---|---|
| Accuracy | 0.673 |
| Sensitivity | 0.636 |
| Specificity | 0.675 |
| PPV | 0.091 |
| AUC | **0.723** |
| 各折 AUC | 0.753 / 0.672 / 0.761 / 0.769 / 0.682 |
| 混淆矩陣 (tn, fp, fn, tp) | (874, 421, 24, 42) |

誠實解讀：
- AUC 從 v1/v2 的 0.674-0.675 提升到 **0.723**，而且各折 AUC 的波動明顯縮小（原本
  0.574-0.809，現在 0.672-0.769）——這是整個迭代過程中第一個讓分類結果真的變好的改動，
  而且改善的來源很清楚：**不是演算法變聰明了，是把 20 位幾何假設不成立的病人（軸切面
  重組影像）排除掉，雜訊資料變少了**。這點值得特別記下來，因為它跟「改用連通元件分析」
  （有改善方法學但沒改善準確度）形成對照：資料品質問題解決帶來的效益，比演算法精緻化
  帶來的效益更大，這是這次練習最重要的心得之一。
- 即便如此，AUC 0.723 仍遠低於「可用於臨床篩檢」的水準（通常期待 AUC > 0.85-0.9）。
- PPV 只有 9.1%：在類別極度不平衡（陽性率不到 5%）的情況下，即使敏感度/特異度都有六成多，
  陽性預測值仍然很低——代表如果拿這個模型去篩檢，每抓出約 11 個「疑似突出」，只有 1 個是真的
  突出，另外 10 個是假警報。這是不平衡資料分類的常見陷阱，不是程式錯誤。

### 特徵係數（僅供參考，不宜過度解讀）

```
bulge_normalized             -0.920
max_bulge_mm                  +0.614
ap_depth_mm                   +0.515
disc_height_mm                +0.485
mean_disc_ap_extent_mm        +0.194
mean_bulge_mm                 +0.168
canal_encroach_frac           +0.117
asymmetry_mm                  +0.096
```

排除幾何不符的病人後，`canal_encroach_frac` 的係數從負轉正（更符合臨床直覺：壓迫比例越高
越像突出），但 `bulge_normalized` 仍然是負的。懷疑仍是跟 `max_bulge_mm` 高度共線（後者就是
前者除以 `ap_depth_mm`），logistic regression 在共線特徵之間把正負號互相抵銷補償——這組
係數不能直接拿來當作「此特徵越大越不像突出」的臨床結論，只能說整組特徵一起用時有判別力，
單一係數的方向不可靠。這是本方法在解釋性上的已知弱點。

### 已知的失敗模式／資料品質問題

- `disc_height_mm` 修正後（v3，中位數＋排除幾何不符病人）整體分布已經合理（中位數約
  9.5mm，符合正常腰椎椎間盤 8-12mm 的範圍），但**殘餘的離群值全部集中在 IVD label=1
  （L5/S1）**：剩下 21/1362 筆（約 1.5%）超過 25mm，全都是 L5/S1 層級，最大 36.5mm。推測
  L5/S1 因為骶骨傾斜角的關係，矢狀面切片上該層級的邊界本來就比其他層級更難用簡單的
  z-extent 量測，這個問題還沒有進一步修正，誠實記錄為已知殘餘限制。
- 1 個椎間盤層級（病人 64 的層級 7）在選用的影像序列中完全沒有抓到對應遮罩體素，可能是該
  序列的視野（FOV）沒有覆蓋到那個層級，已直接跳過並在特徵提取的執行紀錄中列出，沒有隱瞞。
- 椎體 body/後方結構的區分法（以脊椎管中心為界）是粗略近似，在脊椎管消失或變形的切片（例如
  嚴重病變個案）可能失準，導致 `mean_bulge_mm` 甚至出現負值（代表方法把某些切片的參考線
  估計錯了，不是真的「內縮」）。

## 這個練習對真實臨床判讀的參考價值（誠實評估）

**很有限，但方向正確、流程完整。** 具體來說：

- 有參考價值的部分：確認了「用官方分割遮罩算幾何特徵、配合簡單分類器、GroupKFold 驗證」這條
  流程是可以走通的，且 AUC 0.723（排除幾何不符病人後）證明幾何特徵本身並非全無訊號——這給
  未來想做更嚴謹版本（例如真的訓練分割網路、或用更精細的椎體解剖結構分離）的人一個「下限
  基準」可以比較。這次迭代也留下一個具體的方法論心得：**資料品質檢查（排除 20 位軸切面
  誤用為矢狀面的病人）帶來的 AUC 提升（0.674→0.723），比演算法精緻化（連通元件分析，AUC
  幾乎不變）帶來的提升更大**——對這類小樣本醫學影像練習，先把資料真的看懂、篩乾淨，往往
  比急著優化演算法細節更有效益。
- 沒有參考價值／不能直接用於臨床的部分：PPV 仍只有個位數百分比，規則式門檻法幾乎無鑑別力，
  椎體 body 的分離方法仍是近似而非解剖學精確分割，`disc_height_mm` 在 L5/S1 層級仍有殘餘
  離群值問題，且全部驗證都在同一個資料集上做（沒有外部資料集驗證泛化能力）。這些都代表此
  方法**不應該被當作任何形式的診斷輔助**，純粹是學習分割遮罩幾何分析與分類驗證流程的練習。
- 對達文西機器人脊椎手術影像演算法準備工作的意義：比起 `Spine_Screw_Practice`（骨骼 CT 的
  HU 閾值分割），這次練習到的是「軟組織遮罩的幾何量化＋不平衡資料分類評估＋GroupKFold 避免
  資料洩漏」，這些技能跟骨骼分割不重疊，是另一塊需要補的能力版圖。

2. ~~修正 `disc_height_mm` 的離群值問題~~ **已完成（v3）**：改用逐矢狀切片中位數，並加上
   `is_sagittal_multislice()` 幾何檢查排除 20 位實際是軸切面重組影像（而非矢狀面）的病人。
   這個發現比單純改統計量重要得多——離群值的根因是整個演算法幾何假設對這些病人不成立，不是

   層級仍有約 1.5% 的個案高度偏大（見上方驗證結果），原因待查，可能跟骶骨傾斜角有關。
3. 如果之後真的需要原始 MRI 影像（`images.zip`）：排隊讓 Zenodo 慢速下載跑一整晚，或先驗證
   `MedOtter/SPIDER` 這類第三方重傳來源的 checksum 與官方 `masks.zip` 的對應個案完全一致後
   再採用，不要在未驗證的情況下直接信任。
4. 嘗試用更多特徵（例如椎間盤訊號強度——但這需要 `images.zip`）或更合適的模型（例如
   penalized logistic regression 加 L1 做特徵選擇，或簡單的樹模型），評估是否能把 AUC 推高、
   PPV 改善。
5. 用獨立的外部資料集（而非同一個 SPIDER 資料集的交叉驗證折）驗證泛化能力，才能更誠實地評估
   這套方法的實際價值。

## 使用方式

```bash
# 1. 建立虛擬環境（已建好在 .venv/，Python 3.11 + SimpleITK/numpy/pandas/scikit-learn/scipy/matplotlib）
"C:\Program Files\Python311\python.exe" -m venv .venv
.venv\Scripts\python.exe -m pip install SimpleITK numpy pandas scikit-learn scipy matplotlib

# 2. 從下載的 masks.zip 解壓縮到乾淨的資料夾（data_extracted/，跟下載檔案分開存放）

# 3. 抓取幾何特徵
.venv\Scripts\python.exe -I scripts\extract_features.py data_extracted\masks\masks data_raw_download\overview.csv data_raw_download\radiological_gradings.csv results\disc_features.csv

# 4. 跑分類驗證
.venv\Scripts\python.exe -I scripts\classify.py results\disc_features.csv results\classification_report.txt
```
